# ♟ Chess Coach

Тренер для Chess.com из двух независимых частей:

1. **Публичный сайт** — разбор уже сыгранных партий. Stockfish работает в браузере
   посетителя (WebAssembly), партии загружаются из публичного API Chess.com.
   Сервера нет: сайт можно бесплатно разместить на GitHub Pages.
2. **Локальный live-тренер** — панель с оценкой ходов прямо на chess.com.
   Каждый пользователь запускает её на своём компьютере; к автору сайта
   не уходит ни один запрос.

> **⚠️ Fair play.** Правила Chess.com запрещают использовать движок в партиях
> против людей — и в рейтинговых, и в нерейтинговых. Live-панель годится только
> для игры против компьютера, тренировки и разбора уже сыгранных партий.

## Публичный сайт

Откройте страницу и нажмите «Разобрать партию»:

- ник на Chess.com → последние партии из публичного API;
- оценка каждого хода: бриллиант, лучший ход, неточность, ошибка, зевок;
- точность, средняя потеря в сантипешках, худший ход;
- всё считается в браузере: позиции не отправляются ни на сервер, ни автору.

Сайт не использует куки, трекеры и внешнюю аналитику. Единственные внешние
запросы — к `api.chess.com` за партиями. GitHub Pages, как и любой хостинг,
видит IP-адреса посетителей, но автору сайта они не передаются.

### Как разместить на GitHub Pages

1. Создайте публичный репозиторий и загрузите в него проект.
2. Откройте **Settings → Pages**.
3. **Source:** `Deploy from a branch`, **Branch:** `main`, **Folder:** `/docs`.
4. Сохраните и дождитесь сборки. Адрес будет
   `https://<аккаунт>.github.io/<репозиторий>/`.

Файл `docs/.nojekyll` уже лежит в проекте: он отключает обработку Jekyll и
гарантирует, что `vendor/` и `.wasm` отдаются как есть. Все пути в `docs/`
относительные, поэтому сайт работает и в подпапке репозитория.

### Проверка локально

```bash
python3 -m http.server 8000 --directory docs
# http://127.0.0.1:8000/
```

## Локальный live-тренер

Панель на chess.com показывает вердикт после каждого хода. Движок и сервер
работают на компьютере пользователя, сервер слушает только `127.0.0.1`.

### Установка

1. Скачайте репозиторий (`Code → Download ZIP` или `git clone`).
2. Установите Stockfish:
   ```bash
   sudo apt install stockfish
   ```
   На Windows и macOS скачайте сборку с <https://stockfishchess.org/download/>.
3. Установите Tampermonkey или Violentmonkey в браузер.
4. Запустите локальный сервер в папке проекта:
   ```bash
   ./start.sh
   ```
   На Windows: `python server.py`. Если Stockfish не в `PATH`:
   ```bash
   python3 server.py --engine /путь/к/stockfish
   ```
5. Откройте <http://127.0.0.1:8765/> и нажмите «Установить userscript».
   Либо установите его со страницы сайта: `local.html` → «Установить userscript».
6. Откройте chess.com и начните партию. Панель появится справа снизу;
   её можно перетащить за заголовок, двойной клик возвращает в угол.

Ярлык в меню приложений (Linux):

```bash
./install-local.sh
```

Скрипт создаёт `~/.local/share/applications/chess-coach.desktop` с текущим
путём к проекту. В репозиторий этот файл не попадает.

### Параметры сервера

```bash
./start.sh --depth 16 --movetime 2500
```

Глубина 14 — быстрый компромисс (обычно 0,5–1,5 с на ход). 16–18 точнее, но
медленнее; для блица лучше 12.

## Как это работает

### Разбор партии

1. Браузер загружает PGN из публичного API Chess.com.
2. `chess.js` разбирает ходы и FEN-позиции.
3. Stockfish WASM в Web Worker оценивает каждую позицию (MultiPV = 3).
4. `analysis.js` считает потерю вероятности победы, точность, проверяет,
   был ли ход лучшим, и ищет жертву через SEE и материальный убыток
   в главном варианте.
5. Таблица и сводка строятся локально.

Оценки — приближение к классификации Chess.com, а не её официальный алгоритм.

### Live-панель

1. Userscript читает FEN из объекта доски chess.com.
2. При смене позиции отправляет пару FEN «до/после» на `127.0.0.1:8765`.
3. Локальный сервер считает обе позиции Stockfish и возвращает вердикт.
4. Userscript показывает вердикт и историю ходов.

Позиция «после» хода становится позицией «до» следующего, поэтому каждый ход
требует одного нового поиска, а не двух. Логи пишутся в `games/` на локальном
диске.

## Анонимная публикация

Сайт статический, поэтому он не выдаёт компьютер и местоположение автора.
Но публикация в GitHub всё равно связана с аккаунтом. Разумный минимум:

- отдельный GitHub-аккаунт с нейтральным ником, не повторяющим ники в других
  соцсетях;
- почта вида `<id>@users.noreply.github.com` в настройках Git:
  ```bash
  git config user.name "Chess Coach"
  git config user.email "<id>@users.noreply.github.com"
  ```
- проверить, что в коммитах нет личного имени и почты:
  ```bash
  git log --format='%an <%ae>'
  ```
- не коммитить `games/`, `*.log`, локальные ярлыки и бинарники Stockfish —
  они уже перечислены в `.gitignore`;
- помнить, что адрес `https://<аккаунт>.github.io/...` и история коммитов
  публичны. Полной анонимности GitHub не обещает: аккаунт всё равно остаётся
  связанным с владельцем на уровне сервиса.

Перед первым коммитом проверьте, что в проекте нет домашних путей:

```bash
grep -rn "/home/" --exclude-dir=.git --exclude-dir=games .
```

## Если что-то не работает

**«Сервер не запущен» в панели.**
- Окно с `./start.sh` должно быть открыто.
- Проверьте <http://127.0.0.1:8765/health> — должно быть `{"ok": true}`.

**«Stockfish не найден».**
- `sudo apt install stockfish` или укажите путь через `--engine`.

**Панель на chess.com не появляется.**
- Tampermonkey включён, скрипт установлен, вкладка chess.com перезагружена.

**Разбор идёт медленно.**
- Уменьшите глубину до 10–12.
- Закройте другие тяжёлые вкладки: WASM-движок использует CPU.

**Chess.com обновил интерфейс.**
- Скрипт держится за внутренний объект `game` доски. Если Chess.com его
  переименует, нужно поправить `getBoard()` в userscript.
